# 飞书项目 Prompt 最佳实践模式库

本参考文档列出了飞书项目不同场景下的推荐 Prompt 模式，用于将用户需求规范化。内容综合了官方 MCP Prompt 最佳实践与 CEM 团队实际使用经验。

## 0. 主技能输出规范

基础技能必须先输出“规范化指令包”再交给独立 `cem-feishu-project-*` 技能执行。

```json
{
  "router": "cem-feishu-project-basic",
  "task_type": "query|create|update|stats|report|debug",
  "target_skill": "cem-feishu-project-feedback-stats|cem-feishu-project-bug-debugger|cem-feishu-project-weekly-report|未匹配",
  "normalized_instruction": "可执行的规范化指令",
  "parameters": {},
  "output_contract": {
    "format": "markdown",
    "must_include": []
  }
}
```

## 1. 查询指定工作项信息

### 查询节点信息
- **场景**：获取特定 URL 工作项的详细节点或字段。
- **模式**：查询 <飞书项目工作项实例 URL> 中的【节点1】和【节点2】节点相关信息。
- **示例**：查询 https://project.feishu.cn/b/abc 中的【开发中】节点相关信息。

### 查询优先级和处理时长
- **场景**：查询特定空间、类型下工作项的优先级或受理人等。
- **模式**：在【空间名称】空间下，查询【工作项类型】中 <飞书项目工作项实例 URL> 的【字段1】、【字段2】。
- **示例**：在【飞书项目】空间下，查询【需求】中 https://project.feishu.cn/b/abc 的优先级、受理人。
- **扩展**：查看 <飞书项目工作项实例 URL> 的反馈时间的值。

### 缺陷追踪
- **场景**：查看缺陷状态或关联需求。
- **模式**：在【空间名称】空间下，查询 <飞书项目工作项实例 URL> 缺陷的【状态】信息。
- **扩展**：在【空间名称】空间下，查看 <飞书项目工作项实例 URL> 缺陷的关联的需求。

### 查看人员和角色信息
- **模式**：查看 <飞书项目工作项实例 URL> 的【角色名称】是谁。
- **扩展**：查看 <飞书项目工作项实例 URL> 的【角色1】、【角色2】分别是哪些人。
- **扩展**：在【空间名称】空间下，查看【工作项类型】的字段配置信息。

### 查看业务线信息
- **模式**：查看 <飞书项目工作项实例 URL> 的业务线的值。

### 查找关联文档
- **模式**：查看 <飞书项目工作项实例 URL> 的【关联文档1】的值。

## 2. 查询视图下的工作项信息

### 基础数据拉取
- **模式**：在【空间名称】空间下，查询视图 <飞书项目视图 URL> 前20条数据。

### 查询视图中工作项的基础信息
- **模式**：在【空间名称】空间下，查询视图 <飞书项目视图 URL> 前20条数据的【字段信息】。
- **扩展**：在【空间名称】空间下，查询视图 <飞书项目视图 URL> 前20条数据的【字段信息】和创建者。
- **扩展**：在【空间名称】空间下，查询视图 <飞书项目视图 URL> 的所有【附件】信息。
- **扩展**：在【空间名称】空间下，查询视图 <飞书项目视图 URL> 的所有【字段1】信息，并汇总最近分类。
- **扩展**：在【空间名称】空间下，查询视图 <飞书项目视图 URL> 前20条数据的【名称】、优先级和提出时间，并按优先级排序用表格展示。

### 特定流程节点查询
- **模式**：在【空间名称】空间下，查询视图 <飞书项目视图 URL> 在【进行中】的节点信息。
- **扩展**：在【空间名称】空间下，查询视图 <飞书项目视图 URL> ，状态为【开发中】的工作项。

### 查看视图的人员信息
- **模式**：在【空间名称】空间下，查询视图 <飞书项目视图 URL> ，有多少我创建的需求。
- **扩展**：在【空间名称】空间下，查询视图 <飞书项目视图 URL> ，按创建人分组展示。

### 查看图表信息
- **模式**：在【空间名称】空间下，查询视图 <飞书项目视图 URL> 中前5条图表。
- **扩展**：在【空间名称】空间下，查询图表 <飞书项目图表 URL> 的数据。

## 3. 以人员查询

### 查询待办
- **模式**：帮我查一下我的待办中的前50条需求。
- **时间过滤**：帮我查一下我的待办中前100条需求中的近一周的数据。
- **扩展**：查询我这个星期会到期的前50条数据。

### 查看排期信息
- **模式**：帮我查一下【人员姓名】在【空间名称】空间下的近一个月的需求人员排期数据。
- **扩展**：查一下我在【空间名称】空间下的需求人员排期数据，时间周期为 2026-01-01 到 2026-02-28。
- **扩展**：帮我查一下【空间名称】空间下的【人员1】、【人员2】等20人以上的需求人员排期数据，周期为 2026-01-01 到 2026-02-28。
- **扩展**：帮我查一下【人员姓名】在【空间1】空间、【空间2】空间的需求类型，时间为 2026-01-01 到 2026-02-28 的人员排期数据。

## 4. 创建与更新信息

### 创建工作项
- **模式**：在【空间名称】空间里，创建一个名称为"任务名称"、【字段名】为"字段值"的【工作项类型】。
- **示例**：在【研发】空间里，创建一个名称为"功能测试"、优先级为"高"的需求。
- **扩展**：在【空间名称】空间里，创建一个名称为"功能测试"、生产日期为今天的【需求名称】需求。
- **扩展**：在【空间名称】空间里，创建一个名称为"功能测试"、人员操作记录中记录员为【人员】的需求。

### 更新工作项信息
- **模式**：更新 <飞书项目工作项实例 URL> 实例的【字段1】为"测试xxx"、【字段2】为暂无。
- **扩展**：更新 <飞书项目工作项实例 URL> 实例的【字段】为"硬件开发"、【角色】为"用户"。
- **扩展**：在【空间名称】空间里，更新 <飞书项目工作项实例 URL> 实例的【QA】角色为"用户"。
- **扩展**：更新 <飞书项目工作项实例 URL> 实例的【日期字段1】为 2026-02-11、【日期字段2】为"6个月"。
- **清空字段**：在【空间名称】空间里，清空 <飞书项目工作项实例 URL> 实例的【字段】信息。

### 流转节点
- **模式**：完成 <飞书项目工作项实例 URL> 实例的【节点名称】节点。
- **扩展**：完成 <飞书项目工作项实例 URL> 实例的【节点1】和【节点2】节点。
- **回滚**：在【空间名称】空间里，回滚 <飞书项目工作项实例 URL> 实例的【节点】节点，原因为"测试不通过"。

## 5. 统计与报表指令

### Feedback 回收统计
- **场景**：统计 Feedback 回收、数据分层等。
- **模式**：统计视图 <飞书项目视图 URL> 的 feedback 回收情况，并输出分层报告。
- **默认视图模式**：统计默认视图的 feedback 回收情况，按开发上线时间分层。
- **路由目标**：`feedback_investment_stats`

### 研发投入统计
- **场景**：面向 leader 汇报研发小组投入产出。
- **模式**：统计【空间名称】空间下【时间范围】内 feedback 的客户声音填写率、关联 Story/Task 的研发投入耗时，输出综合报告。
- **路由目标**：`feedback_investment_stats`

### 周报生成
- **场景**：生成本周工作汇总。
- **模式**：生成本周周报，包含本周上线任务、feedback 回收情况、下周计划。
- **路由目标**：`weekly_report`

## 6. Bug 调试指令

### Bug 单分析
- **场景**：分析飞书项目 Bug 单并定位根因。
- **模式**：分析 <飞书项目 Bug 单 URL> 的问题，定位根因并修复代码。
- **路由目标**：`bug_debugger`

### 回写调试结论
- **场景**：将调试结论写回飞书项目 Bug 单。
- **模式**：将以下调试结论写回 <飞书项目 Bug 单 URL>：【结论内容】。
- **路由目标**：`bug_debugger`
