# 周报生成子流程

> 本文件为 `cem-feishu-project-weekly-report` 的完整业务规范。
> Meegle CLI（`@lark-project/meegle`）可作为补充工具链，详见 [cem-feishu-project-basic/guidance/meegle-cli-guide.md](../../cem-feishu-project-basic/guidance/meegle-cli-guide.md)。

**CRITICAL — 开始前 MUST 先用 Read 工具读取 [`../../lark-shared/SKILL.md`](../../lark-shared/SKILL.md)，其中包含认证、权限处理。**

**工具链优先级**：飞书项目数据获取严格遵守 **FeishuProjectMCP > Meegle CLI > lark-cli**。MCP 不可用时切换到 `meegle` 命令，两者均不可用时才使用 `lark-cli`。三者均失败则报错通知用户。详见 `cem-feishu-project-basic`「工具链优先级」章节及 [cem-feishu-project-basic/guidance/meegle-cli-guide.md](../../cem-feishu-project-basic/guidance/meegle-cli-guide.md)。

飞书项目数据统一通过全局 `FeishuProjectMcp` 获取；飞书/Lark CLI 统一使用本机全局 `lark-cli`，禁止调用项目内 `node_modules/.bin/lark-cli`。

## 工作流

```
信息源 ─┬─► 本周上线任务视图 ──────────────► 提取本周任务 + 租户 + 状态
        ├─► 下周计划任务视图 ──────────────► 提取下周计划任务 + 租户信息
        ├─► 本地 Feedback 统计文档 ──────────► 提取反馈统计数据
        ├─► 飞书项目操作记录 ───────────────► 提取客户评价与填写人
        ├─► 飞书/Lark 群聊或用户补充 ───────► 提取本周个人任务项（可选）
        ├─► 产品经理转发的 Feedback/Story ──► 分类纳入下周计划/技术调研/需求厘清
        └─► 云文档（备选开发计划）───────────► 提取 H4 标题及内容（可选）
                    │
                    ▼
              AI 整合与格式化 ──► 生成周报 Markdown
                    │
                    ▼
              写入 outputs 目录 ──► 输出周报文件
```

## 模板结构

### 模板变量说明

| 变量名 | 来源 | 说明 |
|--------|------|------|
| `{截止日期}` | 用户指定 | 周报截止日期，如 "2026-03-27" |
| `{前端人员}` | 静态配置 | 本周前端投入人员，直接写入模板 |
| `{后端人员}` | 静态配置 | 本周后端投入人员，直接写入模板 |
| `{上线任务列表}` | Story 清单视图 | 本周一至周五完成/提测/测试中/进行中的任务，保留实际状态 |
| `{反馈列表}` | 飞书项目操作记录 | 本周更新客户声音的工作项名称、客户评价、客户评价填写人 |
| `{反馈统计}` | 本地 Markdown | 总数、已填/未填数量、本周新增回收数量、分层统计 |
| `{个人任务项}` | 用户补充或飞书/Lark 群聊 | 非 Story 但本周实际投入的排查、优化、支持事项；用一句自然语言概括 |
| `{产品经理转发项}` | 用户补充或飞书项目链接 | 按"确认纳入下周计划 / 待技术调研 / 需需求厘清"分类 |
| `{下周开发计划}` | 下周计划视图+产品经理转发项+云文档补充 | 每项包含任务名、租户、状态、目标/动作/风险 |
| `{技术调研项}` | 下周计划与转发项 | 筛选标题/内容包含"技术调研"或明确需调研的项 |

```markdown
   需需求厘清：
      - {任务名称或链接}
        状态：{状态}
        风险：{如有进度风险，简述}

【用户需求迭代】

1. 下周开发计划：
   a. {任务名称}
      i. 租户：{租户}
      ii. 状态：{状态}
      iii. 目标：{本周确认的下周处理目标；如需先厘清，写"下周动作"}
```

### 结构与表达规则

- **本周上线任务不只写"已完成"**：保留飞书项目或用户确认的真实状态，如"已完成""提测""测试中""进行中""周五才提测，预计下周一上线"。
- **上线时间仅在已确认时填写**：从完成日期、上线字段或用户补充中提取；不可推断。
- **不输出「本周风险与未完成原因」章节**：周报正文不包含该独立章节；风险信息仅在用户明确要求或下周计划项中按需体现。
- **Feedback 清单必须包含填写人**：填写人来自本周最后一次更新 `field_57aa16`（客户声音）的操作记录 `operator`，再通过用户信息查询转换为姓名。
- **本周个人任务项可选但要保留结构**：当用户补充排查、优化、群聊支持等非 Story 工作时，放在 Feedback 之后，用一句自然语言描述清楚，避免展开流水账。
- **产品经理转发项要分类**：明确区分"确认纳入下周计划""待技术调研""需需求厘清"，并把已确认排期项同步进下周开发计划。
- **下周计划要可执行**：每项尽量包含租户、状态、目标/动作；有进度风险时显式写"风险"。
- **无数据时写暂无**：如无独立技术调研项，写"暂无独立技术调研项"，不要留空。

## Step 1: 解析本周上线任务视图

### Step 1.1: 获取工作项列表

**关键信息提取**：
- Story 名称
- Story 状态（保留实际状态）
- 租户信息（自定义字段 `field_2352f3`）
- 经办人（`role_members` -> `经办人`）
- 更新时间（`updated_at`）

**命令示例**：
```bash
# 方式一：使用全局 FeishuProjectMcp 获取视图详情
# URL: https://project.feishu.cn/cem/workObjectView/test/cRua_KtDR?scope=workspaces&node=28722127
FeishuProjectMcp.get_view_detail({"project_key":"cem","view_id":"cRua_KtDR","page_num":1})

# 方式二：使用 Meegle CLI 获取视图详情（MCP 不可用时）
meegle view get --view-id cRua_KtDR --project-key cem --page-num 1
```

**数据提取规则**：
1. **本周任务范围**：优先读取本周视图中的所有任务，不只保留"已完成"；按实际状态输出"已完成/提测/测试中/进行中"等。
2. **上线时间**：仅在飞书字段或用户补充明确时填写，禁止把更新时间直接当上线时间。
3. **租户信息**：提取自定义字段中的租户名称；多个租户用"、"连接。

### Step 2.1: 获取工作项列表

**关键信息提取**：
- Story 名称
- 租户信息
- 状态（进行中/待开发）
- 排期时间（`field_ab5474`）

**命令示例**：
```bash
# 使用全局 FeishuProjectMcp 获取视图详情
```

**数据提取规则**：
1. **下周开发计划**：提取视图中的下周计划任务，并合并用户补充的"产品经理转发且确认纳入排期"的 Story/Feedback。
2. **状态保留**：保留飞书项目当前状态，如"未开始/进行中/待开发"。
3. **技术调研项**：从任务名称、描述或用户补充中筛选包含"技术调研"或明确需调研的项。
4. **需求厘清项**：对需求边界不清但下周需要推进的项，写入下周计划并标注"下周动作"和"风险"。

## Step 3: 读取本地 Feedback 统计文档

### Step 3.1: 读取 Markdown 文件

使用 Read 工具读取 `outputs/` 目录下的 Feedback 统计报告。

**提取关键数据**：
- 上线总 Feedback 数
- 已填写客户声音字段数
- 未填写客户声音字段数
- 分层统计数据（超过 30 天、15-30 天等）

## Step 4: 获取飞书项目 Feedback 详情

### Step 4.1: 获取 Feedback 内容

通过飞书项目 MCP 工具查询 `yt_user_feedback` 类型的视图或工作项。

**提取关键数据**：
- 工作项名称
- 客户声音内容（自定义字段 `field_57aa16`）
- 操作记录中的字段修改信息（`field_57aa16` 客户声音）
- 操作时间（`operation_time` / `op_time`）
- 操作人（`operator`，用于提取"客户评价填写人"）
- 开发上线时间（`field_d7593a`）

**数据提取规则**：
- 仅保留操作记录中修改了 `field_57aa16`（客户声音）的 feedback 工作项。
- 使用该条操作记录的操作时间作为筛选依据，时间范围为本周一 00:00:00 至本周五 23:59:59。
- 同一工作项在区间内有多次修改时，仅保留一次，取**最后一次**客户声音更新记录。
- 将最后一次更新记录的 `operator` 通过用户信息查询映射为姓名，写入"客户评价填写人"。

### Step 5.1: 获取文档内容（备选）

如果视图信息不足，可从云文档获取补充信息。
**URL**：`https://skieer.feishu.cn/docx/IApCdwTinoRxSbx3KXNcfIzBnXb`

## Step 5.5: 整理产品经理转发项与个人任务项

### Step 5.5.1: 产品经理转发项

来源可以是用户补充、飞书项目链接、飞书/Lark 群聊或飞书文档。处理规则：
- **确认纳入下周计划**：写入"响应产品经理转发到快攻的 Feedback"，并同步进入"下周开发计划"。
- **待技术调研**：写入"待技术调研"，并同步进入"技术调研"。
- **需需求厘清**：写入"需需求厘清"，并在下周计划中标注下周动作与进度风险。

### Step 5.5.2: 本周个人任务项

当用户补充非 Story 类工作（如线上问题排查、群聊支持、服务优化、日志补充、监控建设）时，放在"Feedback 相关"之后。

表达要求：
- 用一句通顺自然的话概括。
- 必须包含：涉及租户/对象、问题、已完成动作、后续跟进。
- 不展开群聊流水账，不堆砌技术细节；必要时保留关键服务名，如 `message-capture`、Kafka。
- 示例：`针对草本初色实时会话风险预警推送延迟问题，本周优化了消息截图服务（message-capture），补充了链路跟踪日志，并新增 Kafka 记录报错任务，后续继续观察是否能稳定达到 10 分钟内预警。`

## Step 6: AI 整合与生成周报

### Step 6.1: 数据整合

1. **本周上线任务** ← 本周上线任务视图（默认时间范围：本周一至本周五），保留实际状态与确认上线时间。
2. **反馈列表** ← 飞书项目 Feedback 详情 + 客户声音字段操作记录 + 最后更新人。
3. **统计数据** ← 本地 Feedback 统计文档。
4. **本周个人任务项** ← 用户补充或群聊排查信息，一句话概括。
5. **产品经理转发项** ← 分类为下周计划/技术调研/需求厘清，并同步到下周计划。
6. **下周开发计划** ← 下周计划任务视图 + 产品经理转发项 + 云文档补充。
7. **技术调研项** ← 从下周计划、转发项和需求厘清项中筛选。

### Step 6.2: 格式化周报

按照模板结构生成 Markdown 文档：
- 时间范围默认为本周一至本周五
- 使用序号和缩进保持层次结构
- 租户信息格式统一为 "租户：{名称}"
- 状态信息使用真实状态或用户确认描述，不强行改写为"已完成"
- 客户评价填写人必须来自最后一次客户声音字段更新操作人
- 个人任务项用一句自然语言，不拆成过短字段，也不写成排查流水账
- 链接使用飞书项目 URL 格式；正文中可按用户偏好省略链接
- 人员投入使用静态配置（朱伟生/杨天成）

### Step 6.3: 输出文件

保存到 `outputs/{YYYY-MM-DD}_周报.md`。

**重要规则**：
- **禁止写入元信息**：元数据说明（如 `**📋 数据说明**`）、补充说明（如 `**🔧 信息补充说明：**`）及提示信息（如 `**💡 提示**：`）仅允许出现在对话回复中，**严禁写入生成的 Markdown 文件正文**。Markdown 文件应仅包含周报的正文内容。

## Step 7: 处理特殊情况

### 情况 1: 时间范围处理

**默认时间范围**：
- **本周一至本周五**（工作日历）
- 本周上线任务筛选：完成/更新时间在本周一至本周五范围内
- 用户可自定义时间范围：`--start "2026-03-24" --end "2026-03-28"`

### 情况 1: 数据源缺失字段

**缺少租户信息**：
- 从 Story 清单的"租户"字段提取
- 如果没有，标记为"未指定租户"

**缺少客户评价**：
- 从飞书文档中标记为"暂无客户反馈"
- 在统计时归入"未填写客户声音字段"

### 情况 2: 数据不一致

**Story 清单与 Feedback 统计不匹配**：
- 以飞书项目数据为准
- 在周报中添加注释：数据来源于 XX 视图，统计时间 YY

### 情况 3: 周报时间范围

**默认时间范围**：
- **本周一至本周五**（工作日历）
- 本周任务筛选：读取本周视图内任务并保留真实状态；完成/上线时间仅在明确字段或用户补充时使用
- 用户可自定义时间范围：`--start "2026-03-24" --end "2026-03-28"`

```
用户："生成 2026 年 3 月 21 日至 27 日的周报"
AI：使用指定时间范围过滤 Story 清单数据，其余流程相同
```

## 权限要求

| 操作 | 所需权限 |
|------|---------|
| 读取飞书项目 Story 清单 | `project:project.story:read` |
| 读取飞书文档内容 | `doc:doc:read` |
| 写入本地文件 | 本地文件系统写权限 |

## 数据校验

### 必填字段检查

- 周报截止日期
- 本周任务清单非空，且状态/租户尽量完整
- Feedback 统计总数 > 0

### 质量检查

- 租户信息完整性（每个任务都有租户）
- 客户评价不为空（已填写部分）
- 统计数据一致性（总数 = 已填 + 未填）

## 注意事项

1. **时间范围处理**：
   - **本周任务时间范围：本周一至本周五**
   - Story 清单保留真实状态，如已完成、提测、测试中、进行中
   - 上线时间仅在飞书字段或用户补充明确时填写
   - Feedback 相关子项按操作记录过滤，只取本周修改 `field_57aa16` 的工作项
   - Feedback 统计使用当前最新版本

2. **人员投入**：
   - 使用静态文本，无需动态提取
   - 模板中固定为：前端：朱伟生，后端：杨天成

3. **下周开发计划来源**：
   - 从云文档 https://skieer.feishu.cn/docx/IApCdwTinoRxSbx3KXNcfIzBnXb 提取
   - 解析 H4 标题的日期区间（如：3.17-3.21）
   - 只取**前 2 个 H4 标题**及其内容
   - H4 下的列表项格式：任务名称 + 租户信息

4. **技术调研项识别**：
   - 从下周开发计划中筛选
   - 标题或内容包含"技术调研"关键字即识别为技术调研项

5. **租户信息提取**：
   - 优先从 Story 的"租户"字段提取
   - 多个租户用"、"分隔

6. **客户评价格式**：
   - 保留原文，不做改写
   - 暂无评价的标注为"暂无客户反馈"

7. **链接生成**：
   - 工作项链接：`https://project.feishu.cn/cem/test/detail/{WORK_ITEM_ID}`
   - 保持可点击格式
