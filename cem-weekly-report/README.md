# 周报生成器使用指南

## 快速开始

### 1. 基本使用

```
用户："生成本周周报"
AI："请提供以下信息：
1. 本周上线任务视图 URL（默认：https://project.feishu.cn/cem/workObjectView/test/cRua_KtDR?scope=workspaces&node=28722127）
2. 下周计划任务视图 URL（默认：https://project.feishu.cn/cem/workObjectView/test/jWbp3KpDR?scope=workspaces&node=28723183）
3. Feedback 统计文档路径
4. 本周用户反馈列表文档 URL
5. 截止日期（默认：本周五）"

注意：
- 时间范围默认为本周一至本周五
- 人员投入使用静态配置（朱伟生/杨天成）
- 飞书项目数据统一通过全局 `FeishuProjectMcp` 获取
- 周报可合并用户补充的个人任务项与产品经理转发项
```

### 2. 完整参数示例

```
用户："根据以下信息生成周报：

## 数据源说明

### 1. 飞书项目视图

**本周上线任务视图**：
- **用途**：提取本周任务（Story）、租户信息、当前状态及已确认上线时间。
- **URL**：`https://project.feishu.cn/cem/workObjectView/test/cRua_KtDR?scope=workspaces&node=28722127`

**下周计划任务视图**：
- **用途**：提取下周计划开展的任务（Story）及租户信息。
- **URL**：`https://project.feishu.cn/cem/workObjectView/test/jWbp3KpDR?scope=workspaces&node=28723183`

**必需字段**：
- Story 名称
- 租户信息
- 开发人员
- 状态（已完成/提测/测试中/进行中/未开始等真实状态）
- 计划上线时间

### 2. Feedback统计文档

**用途**：提供反馈统计数据

**文件格式**：Markdown

**默认路径**：`outputs/YYYY-MM-DD_Feedback回收情况统计报告.md`

**必需数据**：
- 上线总Feedback数
- 已填写客户声音字段数
- 未填写客户声音字段数
- 分层统计（超过30天、15-30天等）

### 3. 飞书文档用户反馈列表

**用途**：提取客户反馈处理细节

**文档URL示例**：
```
https://skieer.feishu.cn/docx/XYL4dwRxdovrMYxCSWzuzQ88nfc
```

**必需内容**：
- 工作项名称
- 客户声音内容
- 工作项ID（可选，用于生成链接）

### 4. 下周开发计划云文档

**用途**：提取下周开发计划和技术调研项

**固定URL**：
```
https://skieer.feishu.cn/docx/IApCdwTinoRxSbx3KXNcfIzBnXb
```

**解析规则**：
- 提取前2个H4标题（日期区间格式，如：3.17-3.21）
- 每个H4下的列表项包含：任务名称、租户信息
- 从内容中筛选标题/内容包含"技术调研"的项

**时间范围**：
- 默认：本周一至本周五（用于筛选本周上线任务）

### 5. 产品经理转发项与个人任务项

**用途**：补充视图之外但本周实际发生的协作、排查和下周排期信息。

**产品经理转发项分类**：
- 确认纳入下周计划：同步写入“响应产品经理转发到快攻的 Feedback”和“下周开发计划”。
- 待技术调研：同步写入“待技术调研”和“技术调研”。
- 需需求厘清：写入“需需求厘清”，并在下周计划中标注下周动作与进度风险。

**本周个人任务项**：
- 放在 `Feedback相关` 之后。
- 用一句自然语言描述清楚涉及租户/对象、问题、已完成动作和后续跟进。
- 不展开群聊流水账，不把排查细节写成过长列表。

```

## 常见问题

### Q1: 如何自定义周报时间范围？

**答**：在请求中指定 `--start` 和 `--end` 参数

```
用户："生成2026年3月21日至27日的周报"
```

### Q2: 如果缺少租户信息怎么办？

**答**：AI会自动标记为"未指定租户"，你也可以手动补充

### Q3: 客户评价为空怎么处理？

**答**：会标记为"暂无客户反馈"，并在统计时归入"未填写客户声音字段"

### Q4: 数据不一致怎么处理？

**答**：以飞书项目数据为准，周报中会添加数据来源注释

### Q5: 时间范围是如何定义的？

**答**：默认时间范围为本周一至本周五。  
- Story清单优先读取本周视图内任务，保留真实状态，不只限“已完成”。
- 上线时间仅在飞书字段或用户补充明确时填写。
- Feedback相关子项按操作记录过滤，只统计本周修改 `field_57aa16`（客户声音）的 feedback 工作项；同一工作项多次修改仅记一次，取最后一次更新人作为“客户评价填写人”。

### Q6: 下周开发计划是如何提取的？

**答**：从固定的云文档URL（https://skieer.feishu.cn/docx/IApCdwTinoRxSbx3KXNcfIzBnXb）中提取：
1. 解析所有H4标题（通常是日期区间格式，如：3.17-3.21）
2. 只取前2个H4标题及其内容
3. 每个H4下的列表项包含任务名称和租户信息
4. 同时筛选出标题/内容包含"技术调研"的项作为技术调研部分

## 工作流程图

```
┌─────────────────┐
│  用户提供信息   │
└────────┬────────┘
         │
         ├─► Story清单视图URL
         ├─► Feedback统计文档路径
         ├─► 用户反馈/群聊补充（可选）
         ├─► 产品经理转发项（可选）
         ├─► 下周开发计划云文档（固定URL）
         └─► 截止日期（默认本周五）
         
         ▼
┌─────────────────┐
│   AI自动执行    │
└────────┬────────┘
         │
         ├─► Step 1: 解析Story清单
         │         └► 提取本周任务+租户+状态+上线时间
         │
         ├─► Step 2: 读取下周开发计划云文档
         │         ├► 解析H4标题（提取前2个日期区间）
         │         ├► 提取开发计划列表
         │         └► 筛选"技术调研"项
         │
         ├─► Step 3: 读取Feedback统计
         │         └► 提取统计数据
         │
         ├─► Step 4: 获取客户反馈
         │         └► 提取评价、填写人和统计口径
         │
         ├─► Step 5: 整理补充项
         │         ├► 个人任务项一句话概括
         │         └► 产品经理转发项分类并合入下周计划
         │
         └─► Step 6: 整合生成周报
                   └► 输出到outputs目录
         
         ▼
┌─────────────────┐
│  输出周报文件   │
└─────────────────┘
```

## 技术细节

### 依赖的Skills

1. **lark-shared**: 认证和权限管理
2. **lark-doc**: 飞书文档内容读取（用户反馈列表+下周开发计划云文档）
3. **cem-feishu-project-optimizer**: 飞书项目数据提取

### 数据源配置

**固定配置**（无需每次指定）：
- **下周开发计划云文档**：https://skieer.feishu.cn/docx/IApCdwTinoRxSbx3KXNcfIzBnXb
- **人员投入**：前端：朱伟生，后端：杨天成
- **时间范围**：本周一至本周五

**动态配置**（每次需指定）：
- Story清单视图URL
- Feedback统计文档路径
- 用户反馈列表文档URL
- 截止日期（默认本周五）

### 权限要求

- 飞书项目读取权限：`project:project.story:read`
- 飞书文档读取权限：`doc:doc:read`
- 本地文件写入权限

### 数据校验

**必填项检查**：
- ✅ 周报截止日期
- ✅ 本周任务清单非空，且状态/租户尽量完整
- ✅ Feedback统计总数 > 0

**质量检查**：
- ✅ 租户信息完整性
- ✅ 客户评价不为空
- ✅ 统计数据一致性
