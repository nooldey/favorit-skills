# 专利交底书问答清单

当材料不足时，从以下问题中选择最关键的 3-8 个询问用户。不要一次性抛出全部问题。

## 一、基础信息

1. 发明名称是否已有？如果没有，请提供 3-5 个关键词。
2. 这是“方法”“系统”“装置”“存储介质”还是组合申请方向？
3. 发明人、技术交底人、联系方式是否需要写入？
4. 输出格式是 Markdown、DOCX、在线文档，还是仅在对话中给正文？

## 二、背景与现有技术

1. 当前人工或系统是如何解决这个问题的？
2. 最接近的现有方案、竞品、开源工具或内部系统是什么？
3. 现有方案有哪些缺点？请尽量按“效率、准确性、稳定性、一致性、安全性、成本”分类。
4. 哪些缺点是本发明真正解决的？哪些只是业务痛点？
5. 是否有不能写入专利材料的商业秘密或客户信息？

## 三、核心创新点

1. 本方案最核心的新机制是什么？
2. 哪些步骤是不可缺少的？删掉后方案无法成立的步骤有哪些？
3. 与常规做法相比，新增了哪些数据结构、流程、规则或算法？
4. 是否存在多个创新点？请按重要性排序。
5. 哪些部分已经在产品/代码中实现，哪些只是方案设想？

## 四、技术方案细节

1. 输入是什么？例如配置文件、代码仓库、用户指令、日志、接口数据。
2. 输出是什么？例如文档、配置、版本结果、任务、控制指令、报告。
3. 核心流程分哪几步？是否有流程图或伪代码？
4. 是否有关键数据结构？请给出字段、示例 JSON、表结构或对象关系。
5. 是否有关键算法？请说明算法输入、输出、判断条件和复杂度。
6. 是否涉及 AI/模型/规则引擎？模型如何选择、提示词/规则如何组织？
7. 是否有权限、状态机、缓存、队列、异步任务、重试、回滚？
8. 系统包含哪些模块？各模块如何通信？

## 五、异常与边界

1. 输入缺失、格式错误、权限不足时如何处理？
2. 第三方服务或接口失败时是否重试、降级或人工介入？
3. 是否需要回滚、撤销、幂等、审计日志？
4. 是否有多租户、多环境、多版本、多语言等差异？
5. 是否有安全、隐私或合规要求？

## 六、有益效果

1. 方案带来的效果能否量化？例如耗时从多少降到多少、错误率降低多少。
2. 如果不能量化，能否描述为一致性、可追踪性、自动化程度、稳定性提升？
3. 每个效果对应哪个技术步骤？
4. 是否有实际应用案例或上线数据？
5. 是否有对比实验、用户反馈或内部统计？

## 七、附图与实施例

1. 希望包含哪些附图？流程图、架构图、数据结构图、时序图、状态机图？
2. 是否已有截图、流程图、架构图可以参考？
3. 是否需要写多个实施例？例如基础实施例、增强实施例、实际项目案例。
4. 是否需要把某个产品/项目作为典型应用案例？
5. 案例中哪些名称需要脱敏？

## 八、引证资料

1. 是否有相关论文、专利、技术报告、开源项目或内部文档？
2. 是否需要列出参考链接？
3. 是否有不希望引用的竞品或内部材料？

## 九、最小必要追问模板

当用户只给出“帮我写一个专利交底书”时，优先问：

```text
我可以先起草，但需要确认几个关键点，避免编造技术事实：

1. 发明主题/名称是什么？请给 3-5 个关键词也可以。
2. 现有方案如何做？主要痛点是什么？
3. 你的方案核心流程分哪几步？有没有代码、PRD、软著材料或链接？
4. 最想保护的创新点是哪 1-3 个？
5. 输出要 Markdown、DOCX，还是创建到在线文档？
```

## 十、已知信息摘要模板

向用户追问前，先简要复述：

```text
我目前已知：
- 发明主题：...
- 现有问题：...
- 核心方案：...
- 可写入的技术效果：...

仍需确认：
1. ...
2. ...
```
