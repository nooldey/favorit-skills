# 模板与示例提炼

本参考文件沉淀通用专利交底书模板、客户示例和历史软件类交底书中的可复用结构与写作方法。不要在运行时引用或暴露任何生成本 skill 时使用过的具体文件名、链接、人员、客户或项目名称。

## 一、标准模板结构

通用模板采用表格式八章结构：

1. **发明名称**
2. **发明背景**
   - 说明本发明背景；
   - 描述申请人所知最接近的现有技术；
   - 客观评述现有技术的优缺点、问题或不足。
3. **发明内容**
   - 首先描述本发明所要解决的技术问题；
   - 然后描述技术方案，软件类应描述软件流程；
   - 最后描述有益效果，重点写明新增的不可缺少步骤及其直接效果。
4. **说明书附图**
   - 提供本发明流程图，也可包括结构图、数据结构图、时序图。
5. **应用领域**
   - 列举已知和潜在的技术/产品应用领域及应用方式。
6. **具体实施方式 / 典型应用案例**
   - 与附图对应，描述软件步骤；
   - 软件工程类方案可进一步展开典型项目应用案例，说明项目背景、技术挑战、解决方案实施、实施效果、具体应用场景和技术价值体现。
7. **引证资料**
   - 列出相关参考资料、论文、技术报告等。
8. **其它说明**
   - 补充其它相关信息。
   - 发明人签名、日期、技术交底人、联络电话。

## 二、推荐展开结构

实际写作时，可把八章扩展为以下层次，便于代理人提炼权利要求：

```markdown
## 一、发明名称

## 二、发明背景
### 2.1 现有技术状况
### 2.2 现有技术存在的问题
### 2.3 现有技术的局限性

## 三、发明内容
### 3.1 要解决的技术问题
### 3.2 技术方案
#### 3.2.1 模块/步骤一
#### 3.2.2 模块/步骤二
#### 3.2.3 异常处理/回滚/校验机制
### 3.3 有益效果

## 四、说明书附图

## 五、应用领域

## 六、具体实施方式 / 典型应用案例
### 6.1 实施例一：基础流程
### 6.2 实施例二：增强流程/多环境/多场景
### 6.3 典型应用案例
```

## 三、历史软件类交底书写法要点

历史软件类交底书通常体现出较完整的软件方案写法。推荐写作主线为：

1. 用发明名称限定技术主题；
2. 在发明背景中先写现有技术状况，再分点写现有问题，最后总结现有工具或方案的局限性；
3. 在发明内容中先提出要解决的技术问题，再按技术模块展开方案，最后逐条对应有益效果；
4. 用 3-6 张说明书附图覆盖系统结构、核心算法、数据结构、执行流程、持久化/追踪和多场景管理；
5. 列出应用领域；
6. 用具体实施方式或典型应用案例证明方案如何落地，按“项目背景 → 技术挑战 → 解决方案实施 → 实施效果 → 具体应用场景 → 技术价值体现”展开；
7. 最后补充引证资料和其它说明。

### 1. 背景部分

使用三段式：

- 大型软件系统、工程平台或自动化工具的普遍背景；
- 现有自动化、协作或管理方式的问题；
- 现有工具、脚本或平台能力之间缺乏统一协同的局限性。

问题列举采用编号，每个问题有标题和解释，例如：

1. 组合复杂度高，难以统一管理；
2. 依赖关系或处理链路复杂；
3. 多环境或多场景隔离困难；
4. 异常恢复或回滚复杂；
5. 过程信息追踪困难。

### 2. 发明内容部分

先用一句话定义要解决的技术问题，再按技术模块展开，例如：

1. 统一标识或配置定义机制；
2. 核心信息管理和合并/匹配/生成算法；
3. 多环境或多场景隔离管理；
4. 自动化执行流程；
5. 结果信息持久化与追踪机制。

每个模块下包含：

- 概念定义；
- 数据格式；
- 执行步骤；
- 代码/伪代码示例；
- 算法特点或机制特点。

### 3. 有益效果部分

有益效果与技术方案一一对应，写法示例：

- 通过层级化或结构化配置，降低复杂组合管理难度；
- 通过递归/规则/模型合并算法，实现局部覆盖或增量更新；
- 通过统一标识，实现跨模块、跨流程或跨环境协调；
- 通过环境配置或策略隔离，实现不同场景的独立控制；
- 通过结果信息持久化，实现后续追踪、审计或回滚。

写作原则：每个效果都要能回溯到一个技术特征。

### 4. 附图部分

历史软件类交底书常见附图规划包括：

- 图1：系统或模块结构图；
- 图2：核心算法流程图；
- 图3：关键数据结构图；
- 图4：自动化执行流程图；
- 图5：结果信息持久化结构图；
- 图6：多环境或多场景管理示意图。

软件类专利建议至少覆盖：

- 系统/模块结构图；
- 核心算法流程图；
- 数据结构图；
- 执行流程图；
- 异常处理或回滚流程图；
- 多场景部署/应用示意图。

### 5. 应用领域与应用案例

典型的软件类应用领域可包括：

- 大型软件系统开发；
- 多团队协作开发；
- 多环境部署管理；
- 持续集成和持续交付；
- 故障恢复、审计和追踪。

典型应用案例应包含，并建议按以下段落顺序展开：

1. **项目背景**：说明项目类型、模块构成、参与角色或运行环境；
2. **技术挑战**：把背景问题映射为本方案要解决的工程技术问题；
3. **解决方案实施**：用示例配置、流程、命令、数据结构或模块交互说明方案如何实施；
4. **实施效果**：说明效率、一致性、追踪性、稳定性等技术效果，量化数据必须来自用户材料或标记待确认；
5. **具体应用场景**：列举开发、测试、生产、回滚、审计、协作等场景下的执行方式；
6. **技术价值体现**：回扣复杂度降低、自动化提升、错误减少、追踪增强等价值。

## 四、客户示例写法要点

客户示例通常更接近传统专利说明书叙述风格，其特点：

- 开头直接描述背景和现有技术不足；
- 通过“第一实施例”“第二实施例”描述不同系统连接方式；
- 每个实施例说明模块、连接关系、存储信息、判断逻辑和控制动作；
- 通过“例如”给出具体场景，说明进入/离开限制区域时的处理；
- 附图中的流程图应在实施方式中逐步解释。

可借鉴句式：

- “在第一实施例中，系统包括……还包括……”；
- “该装置用于获取……并分析确定是否……”；
- “在存储单元中，预先设有……”；
- “当……时，……发送……请求；当……时，……发送……解除请求。”

## 五、软件类交底书写作模板句式

### 背景

```text
在……场景中，……被广泛采用。然而，随着……规模增加/复杂度提升，现有方案在……方面存在不足。
```

### 技术问题

```text
本发明要解决的技术问题是：如何提供一种……方法/系统，使其能够在……条件下，实现……，从而解决……问题。
```

### 技术方案

```text
为解决上述技术问题，本发明提供一种……方法，该方法包括如下步骤：
S1，……；
S2，……；
S3，……；
S4，……。
```

### 有益效果

```text
与现有技术相比，本发明至少具有以下有益效果：
1. 通过……，能够……；
2. 通过……，能够……；
3. 通过……，有利于……。
```

## 六、常见软件技术要素清单

撰写时优先追问或提取这些要素：

- 输入数据：用户输入、配置文件、接口请求、事件、代码仓库信息；
- 处理流程：解析、匹配、检索、计算、排序、合并、生成、校验；
- 判断条件：阈值、状态、权限、环境、版本、异常类型；
- 输出结果：文档、配置、任务、日志、通知、构建产物、控制指令；
- 数据结构：JSON、表结构、树、图、队列、状态机、索引；
- 异常机制：重试、回滚、降级、跳过、告警、人工确认；
- 技术效果：效率、准确率、一致性、可追踪性、稳定性、安全性。
