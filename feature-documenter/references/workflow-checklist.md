# 工作流程检查清单 (Workflow Checklist)

> 本清单指导 feature-documenter Agent 完成从信息收集到文档交付的全过程。

## 阶段 1：信息收集 (Information Harvest)

### 超链接处理
- [ ] 遍历每条 URL，记录访问时间
- [ ] 提取标题、发布日期、核心观点（一句话）
- [ ] 若 URL 返回 404，作为«ASSUMPTION» 标注「资料已过期」

### 截图 OCR
- [ ] 识别并记录所有 UI 标签、按钮文本
- [ ] 提取默认值、约束条件（如：字符限制、日期范围）
- [ ] 记录错误态提示、disabled 状态说明、tooltip 内容
- [ ] 对数值列（价格、数量等）标注单位与精度

### 原始文本分类
- [ ] Stakeholder 意见 → 背景模块
- [ ] 技术约束 → 功能设置模块
- [ ] 监管要求 → 使用背景模块（合规背景）
- [ ] 性能指标 → 边界异常模块

### 网络搜索
- [ ] 识别知识空白（算法、标准、竞品实现）
- [ ] 至少搜索 3 个外部来源（学术论文 / 行业标准 / 竞对白皮书）
- [ ] 记录搜索日期与结果 URL

---

## 阶段 2：框架构建 (Skeleton)

- [ ] 生成 Markdown 骨架，包含 6 大模块标题
- [ ] 在每个模块下列出**必填项**（见下表）
- [ ] 为«ASSUMPTION» 项预留占位符

| 模块 | 必填项 | 检查要点 |
| --- | --- | --- |
| 背景 | 问题陈述 + KPI + Stakeholder 地图 | 是否明确"成功"的定义 |
| 功能逻辑 | 伪代码 + Mermaid 流程图 | 是否覆盖所有分支 |
| 设置场景 | Admin Levers + 场景矩阵 | 是否定义了默认值 |
| 公式计算 | LaTeX + 参数表 + 验证代码 | 是否覆盖边界条件 |
| 边界异常 | Timeout + Fallback + 审计 | 是否规定了日志格式 |
| 附录 | 源链表 + 术语表 + Changelog | 是否标注了版本号 |

---

## 阶段 3：内容填充 (Content Fill)

### 算法 / 数学问题
- [ ] 搜索官方标准（ISO / RFC / academia）
- [ ] 列举竞品实现方式（对比表：方案 A vs B）
- [ ] 标注选择理由（成本 / 精度 / 实现复杂度）

### 参数 / 阈值
- [ ] 如有用户提供数据，直接使用
- [ ] 否则搜索行业 benchmark
- [ ] 若无明确数据源，标记«ASSUMPTION» + 日期

### 监管 / 合规
- [ ] 获取最新法规原文链接
- [ ] 引用条款编号与核心要点
- [ ] 列出变更历史（若法规近期修订）

---

## 阶段 4：验证 (Validation)

### 公式验证
- [ ] 编写 Python / JavaScript 验证脚本
- [ ] 涵盖正常、最大、最小、溢出四种场景
- [ ] 嵌入脚本 + 输出结果到 Markdown

### 流程图验证
- [ ] Mermaid 图表本地渲染无错
- [ ] 节点标签与伪代码 1:1 映射
- [ ] 所有菱形决策点有两个出口

### Markdown 检查
- [ ] 运行 markdownlint，无孤行 >100 字
- [ ] 列表项格式统一（- 或 * 或 1.）
- [ ] 代码块有语言标记（```python / ```mermaid）

---

## 阶段 5：交付 (Delivery)

- [ ] 自检清单 (见下方) 全部通过
- [ ] 文件保存到 `outputs/<feature>_spec_v<版本>.md`
- [ ] 附带一份 commit message 候选文案
- [ ] 列出已识别的«ASSUMPTION» 项 + 待用户确认

---

## 质量自检清单

```
- [ ] 所有超链接在过去 24 小时内可访问
- [ ] 截图已完整转录为文字
- [ ] 至少 3 个外部源被引用（来源、日期标注清晰）
- [ ] 每条公式都有 LaTeX 渲染
- [ ] 每条公式都有数值验证脚本
- [ ] Mermaid 图表无渲染错误
- [ ] 所涉及数字均有精度说明（整数/浮点/货币)
- [ ] 无模糊措辞（"可能""据说"）；若有假设，标«ASSUMPTION»
- [ ] 所有术语一致使用（不混用中英俗称）
- [ ] 列表项不超 80 字符，便于扫描
- [ ] Markdown 通过 linter：markdownlint
- [ ] 术语表覆盖所有领域特有用词
- [ ] Changelog placeholder 有日期、版本号占位
```

```markdown
| 假设项 | 原因 | 待确认 |
| --- | --- | --- |

1. 用户审阅，指出遗漏或错误

```

## 常见陷阱 (Anti-Patterns)

🚫 **避免**：
- 使用模糊数字而无单位（"快速"、"大量"）
- 省略公式推导过程（直接给结果）
- 流程图中的决策菱形只有一个出口
- 假设用户了解领域背景，不补充术语表
- 引用链接但无发布日期

✅ **改进**：
- "在 100ms 内返回结果"（含量级）
- "基于库存周转率公式：$\text{TPO} = \frac{\text{COGS}}{平均库存}$...推导..."
- 每个菱形显式标注 Y / N 两个分支
- 6 大模块都含完整术语表
- "[源标题](URL) — 发布日期：2026-03-15"
