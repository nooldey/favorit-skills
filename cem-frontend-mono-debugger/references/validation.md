# 本地验证 validation

本文件定义修复后的验证顺序和记录方式。验证必须真实执行后才能声称通过；无法执行时说明原因和风险。

## 验证顺序

1. **最小验证**：改动文件附近的单测、组件测试、hook 测试、service 测试或相关 Story/mock 检查。
2. **包级验证**：受影响 package 的 typecheck、lint、test、局部 build。
3. **应用级验证**：受影响应用的构建、路由访问、本地浏览器关键路径验证。
4. **回归验证**：共享包或公共组件改动时，检查已知调用方并运行代表性验证。

## 前端行为验证清单

UI 行为修复优先用本地浏览器验证：

- 页面能进入，路由和 query 正常。
- Console 无新增错误或警告。
- Network 请求参数、响应、重复请求、取消请求符合预期。
- loading、empty、error、无权限、只读、空数据状态可见且正确。
- 表单默认值、校验、提交 payload、失败提示、重复提交门禁符合预期。
- 弹窗/抽屉二次打开、关闭、提交中关闭、刷新后恢复符合预期。

## 命令选择原则

- 先在发生变更的子 git 仓库内运行命令。
- 优先使用项目已有脚本和包管理器，不新增依赖。
- 命令超时、缺依赖、环境不可用时记录完整原因。
- 失败时区分“已有失败”和“本次改动导致失败”；不能把失败包装成通过。

## 验证记录模板

```markdown
### 验证记录
| 子仓 | 命令/方式 | 结果 | 说明 |
|---|---|---|---|
|  | `pnpm test ...` | 通过/失败/未执行 |  |
|  | `pnpm typecheck` | 通过/失败/未执行 |  |
|  | 浏览器验证 | 通过/失败/未执行 |  |
```

## 无法验证时必须说明

- 缺少依赖、环境变量、账号权限、后端环境、测试数据或本地服务。
- 哪些风险未覆盖。
- 用户或后续执行者可以补跑的具体命令或操作。
