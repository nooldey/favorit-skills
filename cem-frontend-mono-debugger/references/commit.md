# 代码提交准备 commit

本文件定义修复完成后的提交准备规则。默认只准备提交信息和变更清单，不自动执行 `git add`、`git commit`、`git push`。

## 前置条件

准备提交说明前必须完成：

1. 已确认每个变更文件所属子 git 仓库。
2. 已完成相关验证，或记录无法验证原因。
3. 已完成每个有 diff 子仓的 `code-review-expert` 评审并处理意见。
4. 已读取每个有 diff 子仓的当前分支、变更文件和 diff 摘要。
5. 已确认没有混入无关文件、临时日志、调试代码或敏感信息。

## 禁止事项

- 禁止自动执行 `git add`、`git commit`、`git push`。
- 禁止在 mono 根仓为子仓改动准备错误提交。
- 禁止把多个子仓的提交信息混成一个不可追踪提交。
- 禁止提交未处理的高风险评审问题。
- 禁止为了让工作区干净而删除、重置或覆盖用户改动。

## 提交粒度

- 每个有 diff 的子 git 仓库单独准备提交说明。
- 如果同一子仓包含多个无关修复，建议拆分提交，但必须先告知用户。
- 如果发现无关改动，保留不动并在最终回复中说明，不纳入本次提交建议。

## 提交信息准备

若用户要求提交，执行任何 git 写操作前必须再次确认。提交信息正文使用简体中文，并参考该子仓最新一条 git log 的 message 格式。

准备模板：

```markdown
### 提交准备
| 子仓 | 分支 | 建议提交标题 | 变更文件 | 验证 | 评审 |
|---|---|---|---|---|---|
|  |  |  |  |  |  |

建议提交正文：
- 问题原因：
- 修复方案：
- 验证结果：
- 关联工作项：
```

## 用户确认话术

```markdown
我已准备好以下子仓的提交信息，但不会自动提交。若需要我执行 `git add`/`git commit`，请明确确认目标子仓和提交范围。
```
