# CEM Feedback 投资统计 — 执行参考

## Leader 汇报口径

面向 leader 汇报时遵循以下口径：

- **总耗时口径**：只使用 Task 的实际工时事实值，不含预估。字段 key：`field_23cb2b`（实际工作时间h）。凡有实际工时的 Task 必须计入正式投入，包括已完成、进行中、已撤销、已终止、已关闭和其他状态；状态不能作为排除实际投入的理由。
- **成员工时口径**：以 Task 经办人 + 工时登记人为准。职务类型从 `field_9a3d14` 获取。
- **故事/需求口径**：通过 feedback 的 `field_255b77`（关联需求）和 `field_b70230`（补充关联需求）两个字段追溯 Story。两个字段都属于该 feedback 的投入范围，必须合并后按 Story ID 去重，再查询每个 Story 下游 Task 并累计实际工时。
- **缺陷口径**：若 feedback 通过 `field_7e0763`（关联缺陷）关联缺陷工作项，必须读取缺陷的 `field_2e2aa6`（实际耗时（h））并计入该 feedback 总实际投入和总人天。缺陷实际耗时没有明确前端/后端/测试拆分字段时，不强行归类到三类岗位，需在缺陷明细中单独展示。
- **上线时间口径**：使用 feedback 的 `field_d7593a`（开发上线时间）字段，按用户在指令中给定的闭区间筛选。
- **客户声音口径**：`field_57aa16` 字段值为客户声音原始内容，有值即"已填写"，空值即"未填写"。
- **报告受众为 leader 时**：总览表只展示实际工时与 8 小时工作制人天，不出预估。预估工时保留在第五章 Story 级 Task 明细中作参考。

## 证据记录

每条统计数字必须关联到可鉴定的证据入口：

- **工时记录**：Task ID + 字段 key + 实际值 + 查询工具名称（get_workitem_brief）+ log_id。
- **缺陷耗时记录**：缺陷 ID + 字段 key `field_2e2aa6` + 实际值 + 查询工具名称（get_workitem_brief）+ log_id。
- **关系记录**：Story ID + 关联关系 key + 返回的 Task 列表 ID 清单 + 查询工具名称 + log_id。
- **字段记录**：feedback ID + 字段 key + 返回值 + log_id。
- **异常记录**：查询失败、字段缺失、状态异常等事实概述 + log_id。

## 成员维度

- 如果用户提供了 `team_members` 参数（研发小组成员名单），以该名单为准统计。
- 如果用户未提供成员名单，从所有关联 Task 的经办人字段中提取事实参与人清单。
- 职务类型分类：`u9aoehaye`=前端，`y_729vyvx`=后端，`ewwsa_xpp`=测试。
- 成员统计表包含：姓名、职务、实际工时、占比、涉及 Story 数、涉及 Task 数。

## 风险识别

识别以下风险信号并在报告中标记：

| 风险类型 | 识别条件 |
|---|---|
| 测试未完成即上线 | Task 状态为"进行中"但对应 feedback 上线时间已过或处于验收中 |
| 工时超支 | 实际工时 > 预估工时 × 1.5 |
| 无研发投入 | feedback 无关联 Story 或关联 Story 无关联 Task |
| 客户声音缺失 | feedback 上线超过 7 天但客户声音仍为空 |
| 工时缺失 | Task 无工时登记记录且实际工作时间字段为空 |

## 风险与管控建议

报告第七章输出以下三类风险观察：

### 7.1 上线质量风险
列出测试未完成即上线的 Story/Task，说明风险程度和影响。

### 7.2 资源分布观察
- 成员负载分布（最高负载 vs 最低负载）
- 后端/前端/测试工时占比
- 按批次或时间段的投入趋势

### 7.3 客户声音回收率
- 已填写比例
- 未填写按创建时间分层
- 建议推动 CS 团队补充

## MCP 工具使用注意事项

### 查询主视图
```
get_view_detail(view_id, project_key="cem", fields=[具体字段列表], page_num=1)
```
- 必须提供 `project_key`，否则报错 "project_key is empty"
- `fields` 不能使用 `_all`，会报错 "not supported in batch get work items"
- 先用 `list_workitem_field_config` 获取字段列表，再用具体字段 key
- `has_more=false` 时表示已取完所有数据

### 查询关联 Task
```
list_related_workitem(project_key, work_item_id, relation_id)
```
- Story → Task 的关联关系 ID：`relation_1710874751490`
- **必须用 `relation_id`**，不能用 `relation_field_key`（会报 "field not found"）
- 返回的 list 中可能有重复 Task ID（不同名称），需要去重

### 查询 Task 工时字段
```
get_workitem_brief(project_key, work_item_id, fields=["field_fb844a","field_23cb2b","field_9a3d14"])
```
- `field_fb844a`：预估时间（h）
- `field_23cb2b`：实际工作时间（h），可能为空（进行中）或缺失（已终止）
- `field_9a3d14`：职务类型
